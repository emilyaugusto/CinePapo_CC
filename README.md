# 📋 Contexto do Projeto Original

## 1. Descrição do Projeto Original

### Propósito

O **CinePapo** é uma aplicação web desenvolvida como uma rede social voltada para fãs de cinema.

O projeto busca criar um ambiente próprio para que usuários possam descobrir filmes, compartilhar opiniões, publicar resenhas e interagir com outras pessoas que possuem interesse em cinema.

A proposta surgiu da necessidade de centralizar discussões sobre filmes que normalmente ficam dispersas em redes sociais genéricas, criando uma plataforma específica para esse tipo de interação.

Além da interação entre usuários, o CinePapo também funciona como uma ferramenta para descoberta, recomendação e organização de filmes.

# 👥 Casos de Uso Existentes

## Caso de Uso 1 — Criar uma conta

**Ator:** Novo usuário.

**Fluxo:**

1. Usuário acessa o CinePapo.
2. Seleciona a opção de criação de conta ou autenticação.
3. Realiza cadastro ou autenticação via Google.
4. O sistema identifica que se trata de um novo usuário.
5. O usuário passa pelo processo de criação do perfil.
6. Informa suas preferências.
7. Seleciona até três gêneros cinematográficos favoritos.
8. Finaliza o cadastro.

**Resultado:**  
O usuário passa a possuir um perfil no CinePapo e pode utilizar as funcionalidades da plataforma.

---

## Caso de Uso 2 — Explorar filmes

**Ator:** Usuário autenticado.

**Fluxo:**

1. Usuário acessa a página **Explorar**.
2. Visualiza filmes disponíveis e lançamentos.
3. Pode utilizar a pesquisa para localizar um filme específico.
4. Seleciona um filme.
5. Visualiza suas informações detalhadas.
6. Pode explorar recomendações de filmes relacionados.

**Resultado:**  
O usuário encontra novos filmes e pode interagir com conteúdos relacionados à obra.

---

## Caso de Uso 3 — Avaliar um filme

**Ator:** Usuário autenticado.

**Fluxo:**

1. Usuário pesquisa ou seleciona um filme.
2. Acessa a página do filme.
3. Seleciona a opção de escrever uma resenha.
4. Escreve sua opinião.
5. Informa se a resenha contém spoilers.
6. Publica o conteúdo.
7. A publicação passa a integrar a plataforma.

**Resultado:**  
A resenha fica disponível para interação de outros usuários, respeitando a identificação de spoilers.

---

## Caso de Uso 4 — Organizar filmes

**Ator:** Usuário autenticado.

**Fluxo:**

1. Usuário acessa um filme.
2. Seleciona uma das opções disponíveis.
3. Adiciona o filme como:
   - Visto;
   - Quero Ver;
   - Favorito.
4. O sistema verifica se o filme já está classificado.
5. Atualiza as listas conforme as regras de negócio.

**Resultado:**  
O filme passa a fazer parte da respectiva lista no perfil do usuário.

**Regra adicional:** As listas Vistos e Quero Ver são mutuamente exclusivas. Favoritos funciona de maneira independente.

---

## Caso de Uso 5 — Utilizar a Biblioteca Rápida

**Ator:** Usuário autenticado.

**Fluxo:**

1. Usuário acessa a Biblioteca Rápida.
2. Visualiza recomendações personalizadas ou pesquisa filmes.
3. Seleciona um ou vários títulos.
4. Escolhe a lista desejada.
5. Confirma a operação.
6. O sistema atualiza as listas do perfil.

**Resultado:**  
O usuário consegue organizar vários filmes com menos etapas do que no fluxo de adição individual.

---

## Caso de Uso 6 — Conversar com Matt

**Ator:** Usuário autenticado.

**Fluxo:**

1. Usuário acessa o CineMatch.
2. O assistente Matt apresenta uma saudação personalizada.
3. Usuário envia uma mensagem ou seleciona uma sugestão rápida.
4. O sistema considera as preferências disponíveis no perfil.
5. Matt apresenta uma resposta ou recomendação cinematográfica.
6. O usuário pode abrir os detalhes de um filme recomendado.
7. Quando disponível, pode adicionar o filme às listas diretamente pelo chat.

**Resultado:**  
O usuário recebe uma experiência de recomendação mais personalizada e interativa.

---

## Caso de Uso 7 — Participar do Match da Semana

**Ator:** Usuário autenticado.

**Fluxo:**

1. Usuário acessa o Match da Semana.
2. Visualiza uma seleção de filmes em formato de cartas.
3. Arrasta uma carta ou utiliza os botões disponíveis.
4. Escolhe entre demonstrar interesse, marcar como visto ou passar.
5. O sistema registra as escolhas.
6. Ao concluir a rodada, o sistema registra a participação semanal.

**Resultado:**  
Os filmes selecionados são organizados nas listas e a rodada semanal é concluída.

---

## Caso de Uso 8 — Gerenciar seguidores

**Ator:** Usuário autenticado.

**Fluxo:**

1. Usuário acessa seu perfil ou o perfil de outra pessoa.
2. Abre a lista de seguidores ou seguindo.
3. Pesquisa um usuário, se necessário.
4. Seleciona uma ação disponível.
5. O sistema atualiza o relacionamento.

**Resultado:**  
O usuário consegue acompanhar pessoas com gostos semelhantes e gerenciar suas conexões.

# 🏗️ Arquitetura Atual

O CinePapo utiliza o padrão arquitetural **MVC — Model, View, Controller**.

```text
┌─────────────────────────────────┐
│              VIEW               │
│                                 │
│    Interface / páginas CinePapo │
│    Razor • HTML • CSS • JS      │
└────────────────┬────────────────┘
                 │
                 ▼
┌─────────────────────────────────┐
│           CONTROLLER            │
│                                 │
│       ASP.NET Core / C#         │
│  Requisições e regras de fluxo  │
└────────────────┬────────────────┘
                 │
                 ▼
┌─────────────────────────────────┐
│        MODELS / SERVICES        │
│                                 │
│  Entidades e lógica de negócio  │
└────────┬──────────┬─────────────┘
         │          │
         ▼          ▼
┌─────────────┐ ┌──────────────────┐
│   MongoDB   │ │ Integrações      │
│             │ │ externas         │
│ Dados       │ ├──────────────────┤
│ internos    │ │ TMDB API         │
│             │ │ Gemini API       │
└─────────────┘ └──────────────────┘
```

### Descrição dos componentes

**View**  
Responsável pela interface utilizada pelos usuários, incluindo páginas como feed, explorar, perfil, login, Biblioteca Rápida, Match da Semana, chat com Matt e detalhes dos filmes.

**Controller**  
Recebe as ações realizadas pelos usuários, processa as requisições e realiza a comunicação entre interface, serviços e dados.

**Model**  
Representa as estruturas e entidades utilizadas pela aplicação, como usuários, resenhas, notificações e rodadas do Match.

**Services**  
Centraliza integrações externas e determinadas regras de negócio, incluindo consultas ao TMDB, comunicação com o Gemini e lembretes semanais.

**MongoDB**  
Responsável pelo armazenamento dos dados internos da rede social, incluindo listas, interações e registros temporários.

**TMDB API**  
Fornece dados cinematográficos, incluindo títulos, pôsteres, sinopses, elenco, popularidade e informações de recomendações.

**Gemini API**  
Responsável pelo processamento das mensagens enviadas ao assistente Matt e pela geração de respostas contextualizadas.

# 🔍 Análise da Versão Original

O desenvolvimento realizado no semestre anterior permitiu construir a base funcional do CinePapo.

No novo semestre, o projeto entrou em uma etapa de evolução, utilizando a aplicação existente como ponto de partida para identificar oportunidades de melhoria.

## Pontos analisados

- [x] Experiência do usuário.
- [x] Interface e responsividade.
- [x] Fluxos existentes.
- [x] Performance da aplicação.
- [x] Organização de componentes do código.
- [x] Integração com a API TMDB.
- [x] Funcionalidades sociais.
- [x] Compatibilidade entre desktop e dispositivos móveis.
- [x] Possibilidades de integração com IA.
- [ ] Auditoria completa da estrutura e dos índices do MongoDB.
- [ ] Auditoria completa de segurança e autenticação.
- [ ] Validação sistemática de todos os tratamentos de erros.
- [ ] Testes de desempenho com usuários simultâneos.

### Principais problemas identificados

**1. Lentidão em determinadas páginas**

Algumas ações, como explorar filmes, abrir detalhes e adicionar títulos às listas, apresentavam oportunidades de otimização.

**2. Organização de filmes pouco prática**

O cadastro individual de títulos exigia muitas interações, principalmente para novos usuários que desejavam organizar seu histórico de filmes.

**3. Recomendações pouco contextualizadas**

As sugestões inicialmente dependiam principalmente dos dados retornados pela API externa, sem aproveitar plenamente as preferências do usuário.

**4. Limitações na experiência mobile**

Certos componentes apresentavam problemas de proporção, espaçamento, alinhamento e excesso de informações em telas pequenas.

**5. Interações sociais que poderiam ser simplificadas**

As listas de seguidores, as notificações e as resenhas apresentavam oportunidades para reduzir etapas e facilitar o uso.

**6. Falta de uma experiência de IA integrada**

A plataforma possuía informações relevantes sobre preferências cinematográficas que poderiam ser utilizadas em uma experiência conversacional.

- Registros antigos devem seguir uma política de retenção.

O **CinePapo 2.0** representa a continuidade do projeto desenvolvido no semestre anterior.

Durante o processo, foram desenvolvidas melhorias que abrangem interface, usabilidade, desempenho, personalização, inteligência artificial e funcionalidades sociais.

A integração do assistente **Matt**, utilizando o Google Gemini, representa uma das principais inovações da nova versão, ampliando as possibilidades de interação e recomendação cinematográfica.

A criação da **Biblioteca Rápida** e do **Match da Semana** também contribui para tornar a descoberta e organização de filmes mais dinâmica e personalizada.

Além disso, as melhorias de UI/UX buscaram reduzir a sobrecarga de informações, simplificar os fluxos e aprimorar a experiência de navegação em diferentes dispositivos.

O projeto permanece em desenvolvimento e necessita de validações adicionais de desempenho, segurança, responsividade e comportamento com usuários simultâneos.

Ao final do semestre, espera-se apresentar uma versão mais completa, estável e aprimorada do CinePapo, acompanhada da documentação de sua evolução e das evidências comparativas entre as versões.
